# Tooltips MD3 Specs

Source: <https://m3.material.io/components/tooltips/specs>
Collected: 2026-05-26

## Summary

- The tooltip spec page exposes two current token sets under the live `Default, Light` context: `Tooltip - Plain` and `Tooltip - Rich`.
- Plain tooltips are compact inverse-surface containers: `24dp` high, `8dp` padded, `4dp` corner radius, with inverse-on-surface supporting text set in `body-small` typography.
- Rich tooltips are elevated surface containers: `12dp` corner radius, `3dp` elevation, `surface-container` fill, `on-surface-variant` text, and primary-colored action text and state layers.
- The current typography ramp resolves to `Google Sans Text` for plain supporting text, rich subheads, rich supporting text, and rich action labels.
- Rich tooltip configurations allow an optional headline and up to two text buttons; the measurements figure only specifies padding, so overall height remains content-driven.

## Implementation Notes

- Plain tooltips can be modeled as fixed-height inverse surfaces with a single supporting-text slot. The extracted token set only exposes enabled-state styling, so hover or pressed container variants are not part of this component.
- Rich tooltips split structure and action styling cleanly: the container owns surface, shape, elevation, subhead, and supporting-text tokens, while actions reuse primary-colored label and state-layer tokens with hover `0.08`, focus `0.1`, and pressed `0.1` opacities.
- The current live spec resolves typography to `Google Sans Text`, not the older Roboto-based ramp that appears in some previously collected MD3 docs in this repository.
- Rich tooltip height should be treated as content-driven. The spec only gives padding, elevation, and corner geometry, then documents five content configurations ranging from body-only to subhead plus supporting text plus two buttons.
